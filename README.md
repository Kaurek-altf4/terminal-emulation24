# terminal-emulation24

Учебный эмулятор UNIX-подобной командной строки с графическим интерфейсом Tkinter и ZIP-VFS в оперативной памяти.

## Структура проекта

```text
terminal-emulation24/
├── src/
│   ├── __init__.py
│   └── GUI.py
├── tests/
│   ├── __init__.py
│   └── test_emulator.py
├── scripts/
│   ├── test_*.sh
│   ├── startup_*.txt
│   ├── errors/
│   ├── stage4/
│   └── stage5/
├── vfs/
│   ├── minimal.zip
│   ├── multiple.zip
│   ├── deep.zip
│   └── invalid.zip
├── run.sh
├── run.bat
├── Makefile
├── .gitignore
└── README.md
```

`src` содержит исходный код, `tests` — автоматические проверки, `scripts` — сценарии запуска и команды эмулятора, `vfs` — тестовые архивы. `invalid.zip` намеренно имеет неверный формат для проверки ошибки загрузки.

## Требования

Python 3.9 или новее, Tkinter и графическая сессия. Сторонние пакеты Python не нужны. Для Linux-сценариев используется Bash. Если Tkinter отсутствует, установите пакет Tkinter/Tk средствами своей ОС. Автоматические тесты не открывают настоящее окно, но требуют доступного модуля Tkinter.

## Запуск

Из корня проекта в терминале Linux:

```bash
bash run.sh
```

По умолчанию загружается `vfs/minimal.zip`. Пример с другим архивом и стартовым скриптом:

```bash
bash run.sh --vfs ./vfs/deep.zip --script ./scripts/startup_deep.txt
```

Справка:

```bash
bash run.sh --help
```

В Windows при установленном Python с Tkinter:

```bat
run.bat --vfs vfs/deep.zip --script scripts/startup_deep.txt
```

Относительные пути в параметрах `run.sh` и `run.bat` считаются от корня проекта. После запуска команды `ls`, `cd`, `clear`, `uptime`, `chmod` и `exit` вводятся в окно эмулятора. Команды Bash нужно вводить в терминал ОС.

## Проверки

Из корня проекта:

```bash
python3 -m unittest discover -s tests -v
```

Или:

```bash
make test
```

Набор включает 52 автоматических теста: парсер, параметры запуска, загрузку ZIP, пути VFS, base64, команды, права, остановку скрипта при ошибке и запуск из другой папки. GUI-обработчики проверяются с тестовыми виджетами, поэтому эти проверки не заменяют визуальный просмотр настоящего окна.

Примеры проверки через GUI:

```bash
bash scripts/test_vfs_minimal.sh
bash scripts/test_vfs_multiple.sh
bash scripts/test_vfs_deep.sh
bash scripts/test_stage4.sh
bash scripts/test_stage5.sh
```

Ошибочные случаи:

```bash
bash scripts/test_invalid_paths.sh
bash scripts/test_all_commands.sh
bash scripts/test_stage4_errors.sh
bash scripts/test_stage5_errors.sh
```

Запускайте сценарии по одному. В наборах с несколькими запусками закрывайте текущее окно, чтобы перейти к следующему. Ошибки в соответствующих сценариях ожидаемы: первая ошибка останавливает текущий стартовый скрипт. Команда `clear` намеренно стирает предыдущие строки вывода.

## Поддерживаемые команды

| Команда | Назначение |
| --- | --- |
| `ls [путь]` | Содержимое папки VFS |
| `ls -l [путь]` | Просмотр прав папки или указанного файла |
| `cd [путь]` | Переход внутри VFS; без аргумента — в `/` |
| `clear` | Очистка вывода |
| `uptime` | Время работы эмулятора |
| `chmod [-R] MODE PATH [PATH ...]` | Изменение прав в памяти |
| `exit` | Завершение приложения |

`chmod` поддерживает права `000`–`777`, форму `0xxx`, буквенные режимы с явно заданными `u`, `g`, `o`, `a` и операциями `+`, `-`, `=` для `rwx`. Например: `chmod 644 /docs/guide.txt` или `chmod u+x,go-w /docs/guide.txt`. Специальные биты, `X` и копирование прав вида `g=u` не реализованы.

Права — метаданные VFS: проверки доступа по пользователям нет. ZIP открывается только для чтения, файлы не извлекаются на диск. После закрытия программы изменения VFS теряются. Переменные окружения раскрываются по данным реальной ОС, но полученные пути команд ищутся внутри виртуального архива.

## Выполненные этапы

## Этап 1. REPL

Создан графический интерфейс для ввода команд и вывода результатов.

В заголовке окна отображаются реальные имя пользователя и имя компьютера.

Добавлен разбор команд с поддержкой кавычек и переменных окружения ОС.

Реализованы команды-заглушки ls, cd и команда завершения exit.

## Этап 2. Конфигурация

Добавлены параметры запуска --vfs и --script.

При запуске отображаются значения параметров.

Реализовано выполнение команд из стартового текстового файла.

Команды и результаты отображаются в окне эмулятора.

Скрипт останавливается при первой ошибке.

Добавлены Linux-скрипты для проверки параметров запуска.

## Этап 3. Виртуальная файловая система

Реализована загрузка VFS из ZIP-архива в оперативную память.

Содержимое файлов хранится в формате base64.

Архив не извлекается на диск и не изменяется.

Команды ls и cd переведены на работу с VFS.

Поддержаны абсолютные и относительные пути, `.` и `..`.

Добавлена обработка ошибок загрузки архива.

Подготовлены архивы и скрипты проверки: минимальная VFS, несколько файлов и три уровня вложенности.

## Этап 4. Основные команды

Реализована работа ls и cd с виртуальными папками.

Добавлена команда clear для очистки области вывода.

Добавлена команда uptime, показывающая время работы эмулятора.

Подготовлены стартовые скрипты для проверки команд и обработки ошибок.

## Этап 5. Дополнительные команды

Добавлена команда chmod для изменения прав объектов VFS в памяти.

Поддержаны числовые права, например 644, и буквенные изменения, например u+x.

Добавлены рекурсивный режим -R и обработка нескольких путей.

Добавлен вывод прав через ls -l.

Реализована обработка неверных режимов, отсутствующих путей и недостатка аргументов.

Подготовлены стартовые скрипты для проверки команды.

Права хранятся как метаданные VFS: проверка доступа по пользователям не реализована. Изменения прав не записываются в ZIP и сбрасываются при перезапуске.
